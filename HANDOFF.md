## Что это

Очистка диска Windows в одном `.exe` (~280 КБ) на каркасе Lighter (`..\Lighter`): тот же стек, палитры,
движок анимаций, переходы и контролы. Четыре вкладки:

- **Очистка** — большое кольцо (логотип) + «Очистить», категории с галочками справа, карточка «Автоочистка».
- **Программы** — классические (реестр Uninstall) и Microsoft Store (Appx), отметить → удалить очередью, затем остатки.
- **Браузеры** — профили Chromium-браузеров и Firefox: кэш / cookie / история / сеансы; список расширений.
- **Файлы** — большие файлы и дубликаты, удаление в Корзину.

Автоочистка и автозапуск по умолчанию **выключены**.

## Сборка и релиз

- `build.cmd` → `bin\WispCleaner.exe` встроенным `csc.exe` (C# 5). `build.cmd dev` → ещё `bin\WispCleaner.dev.exe`
  с `asInvoker` (запускается без UAC — для проверок).
- Иконка: `tools\MakeIcon.cs` рисует `obj\app.ico` кодом из `src\Logo.cs`. `obj\MakeIcon.exe app.ico --png <папка>` сохраняет PNG всех размеров.
- Релиз: как в Lighter — `.github\workflows\release.yml` собирает по тегу `vX.Y.Z` и публикует exe + `.sha256`.

## Логотип

Метла контуром (одна толщина линии) внутри открытого кольца Lighter: фиолетовый `#9D6BFF` на тёмно-серой
плитке с лёгким вертикальным градиентом `#33353B → #27282C`. Кольцо — 247° от 12 часов по часовой стрелке,
круглые концы. Рисуется в `Logo.Draw` в координатах 256 × 256; на размерах меньше 40 px линии толще, а метла
чуть меньше, чтобы не сливаться с кольцом.

Выбор шёл в три раунда (первые версии — кольцо с пылью, затем кольцо с заливной метлой — показались
непонятными). Листы с вариантами лежат в корне: `logo-variants.png` (6 метафор: пузыри, искра, метла, ветер,
скребок, капля) и `logo-brooms.png` (6 минималистичных метел; выбран № 2 «Контур в кольце»). Исходники листов —
SVG/HTML, рендер — headless Edge; в репозиторий не входят.

Большое кольцо на вкладке «Очистка» (`Logo.DrawMark`, `CleanRing`) осталось прежним — кольцо с пылью и искрой
без метлы, потому что в центре — цифры: вращается при анализе, заполняется при очистке, искрится в конце.

## Плавность и масштабирование

- **Масштаб интерфейса следует за размером окна** (`Theme.Zoom`): 1 при окне 1180×720 (базовый размер),
  растёт шагами по 0,1 до 1,6 (развёрнутое окно на 1920×1080 — 1,4). Масштабируются шрифты, иконки, высоты
  строк, кнопки, панели — всё, что задано в «дизайн-пикселях» через `Theme.S()`. Для каждого шага держится
  свой набор шрифтов; `MainForm.ApplyZoom` обходит дерево контролов: шрифт меняется на ту же роль нового
  набора (`Theme.Remap`), контролы с собственным размером (`IScalable`) пересчитывают его, страницы
  раскладываются заново. Небольшой гистерезис не даёт масштабу «дрожать» при перетаскивании рамки.
  Смена шага стоит 55–100 мс один раз на шаг. Вторичные окна открываются в текущем масштабе.
- **Акцент — фиолетовый** (`Theme.Dark/Light.Accent` = `#8B5CF6` / `#7C3AED`, выделение строк в тон):
  кнопки, переключатели, галочки, вкладки, полоса загрузки.
- **Иконки категорий** рисуются контуром глифа (`GlyphShape`): по центру рисунка, а не текстового поля,
  одного размера и утолщены обводкой того же цвета (у Segoe MDL2 только тонкое начертание).
- **Раскладка тянется за окном.** На «Очистке» левая колонка занимает ~38 % ширины (320–640 px), кольцо
  заполняет её (до 600 px), цифра и подпись в кольце растут вместе с ним (`CleanRing.FitFonts`), кнопка — тоже.
  Колонки всех таблиц делят ширину по весам (`ColumnWeights`) с минимумами (`ColumnMins`), заголовок таблицы
  закрашен до правого края (`HeaderFiller`). «Браузеры» на узком окне делятся 50/50, на широком — 56/44.
- **Переход между вкладками** (`Transition.CrossFade`): снимок «до» копируется с поверхности окна одним blit
  (`GdiBitmap.CopyFromScreen`, ~10 мс вместо 20–55 мс рендера через `WM_PRINT`); снимок «после» —
  `WM_PRINT`. Если внутри области уже идёт переход, вложенный не перебивает его, а ставится в очередь и
  стартует сразу после (`Overlay.Then`) — раньше список мог «прыгнуть» в конце анимации вкладки.
- **Часы анимаций стартуют с первого кадра** (`Anim`): работа между запуском анимации и первым кадром
  (снимки, раскладка) больше не съедает её начало — нет рывка вперёд.
- **Таблицы рисуются строкой целиком** (`ThemedListView.CustomDraw`): `NM_CUSTOMDRAW` перехвачен до WinForms
  (тот звал код на каждую ячейку с новыми объектами), строка рисуется в DIB-буфер (`RowBuffer`: фигуры —
  GDI+ прямо в память, текст — GDI `DrawTextW`), на экран — одним `BitBlt`. Иконки масштабируются один раз.
- **Загрузки скрыты.** «Программы» и «Браузеры» грузятся в фоне через 1,2 и 2 с после старта
  (`Page.Preload`), к первому открытию вкладки списки готовы. Пока данных нет — мерцающие заглушки строк
  (`Shimmer`, `CategoryList.Loading`, `ThemedListView.Loading`), смена на данные — плавным переходом.
  Пустые списки — с крупной иконкой (`EmptyGlyph`).
- **Окна.** Перед проявлением окно (главное и вторичные) отрисовывается целиком (`WindowFx.PaintNow`), после —
  снимается layered-стиль (`WindowFx.EndFade`). Анализ на «Очистке» стартует после проявления окна.
- **Замеры** (окно 1500×900, RDP-сессия): подготовка перехода вкладки 25–60 мс (было 50–130 мс), кадр перехода
  2–5 мс, пропусков кадров во время переходов нет; отрисовка 24 строк «Программ» ~25 мс (было ~50 мс).
  Развёрнутое окно (масштаб 1,4): подготовка перехода 27–60 мс, работа кадра p95 12,5 мс, пропусков нет.
- **Диагностика:** `set WISP_FRAMELOG=C:\путь\frames.log` перед запуском — в файл пишутся кадры
  (`F` штамп, опоздание, работа, число анимаций), переходы (`T` с временем снимков), отрисовки таблиц (`P`)
  и кадры оверлея (`O`). Без переменной ничего не пишется.

## Принудительное удаление, чистка реестра, все пользователи

- **Программы, которые не удаляются.** У записи, чей деинсталлятор пропал с локального диска (или MSI-продукт,
  которого не знает установщик Windows), красная точка и статус «Деинсталлятор не найден». Если штатное удаление
  не удалось, Wisp сразу предлагает принудительное. Его же запускают кнопка «Принудительно» и контекстное меню.
- **Принудительное удаление** (`ForceUninstall.Scan`, как «Force uninstall» в Bulk Crap Uninstaller): деинсталлятор
  не запускается; собирается всё, что ссылается на папку программы: сама папка (`InstallLocation` или папка
  иконки/деинсталлятора), данные в AppData всех профилей, запись удаления, ключи `Software\<издатель>\<имя>`,
  регистрация MSI (`Installer\Products|Features|UserData`, UpgradeCodes), службы и драйверы, задачи Планировщика,
  автозапуск (`Run`/`RunOnce` + `StartupApproved`), App Paths, COM-классы (`InprocServer32`/`LocalServer32`),
  ярлыки в «Пуске», на рабочих столах и панели задач. Список показывается с галочками; то, в чём нет уверенности
  (папка с чужим именем или с другой программой внутри, драйвер), не отмечено.
- **Порядок удаления** (`LeftoverRemover`): службы (stop + delete) → процессы из удаляемых папок (перед этим окно
  со списком «что будет закрыто: программа — пользователь, сеанс») → задачи → значения и ключи реестра → ярлыки
  (пустые папки «Пуска» тоже) → папки в Корзину → **последней — запись удаления программы**, и только если её
  папки удалились (иначе запись остаётся, чтобы повторить). Перед удалением каждый ключ экспортируется в
  `WispCleaner Backup\<дата время>\NNN имя.reg` (папка всегда новая), задачи — в `.xml`, полные пути — в
  `index.txt`. Нет копии — ключ не удаляется; ключ с `"` в имени не трогается.
- **Правила безопасности** (после независимой проверки кода):
  - после перезагрузки (`MoveFileEx`) удаляется только **занятый** файл (нарушение совместного доступа или запущенный
    образ), у которого реальный путь папки внутри удаляемой; «нет доступа», «за пределами», ссылки — никогда;
  - папка отмечается, только если её имя — имя программы (целое слово от 4 букв, `Leftovers.NamedAfter`), она не
    общая (`InstallShield Installation Information`, `Package Cache`, `Common Files`…) и не касается папок программ,
    которые остаются (`Keep`: их `InstallLocation` + папки деинсталлятора и иконки; переменные раскрыты);
  - при удалении папка сверяется с найденной: реальный путь тот же, ни один уровень пути не стал ссылкой;
  - имя, которое есть и у оставшейся программы («Python 3.11» и «3.12» → `Python`), — без галочки;
  - данные других пользователей — без галочки, с именем пользователя; у программы одного пользователя ищется только
    в его профиле и реестре;
  - значения из реестра пользователя (`%LOCALAPPDATA%` и т. п.) раскрываются в **его** профиль
    (`UserProfiles.Expand`), неизвестное не раскрывается и не судится; «файла нет» — только при
    ERROR_FILE/PATH_NOT_FOUND (нет доступа ≠ нет файла), для 32-битных записей проверяются `SysWOW64` и
    `Program Files (x86)`;
  - задача Планировщика отмечается, только если программа — её команда (упоминание в аргументах — без галочки);
    `StartupApproved`: `Run32` только для 32-битного `Run` машины, для `RunOnce` — ничего;
  - пока идёт удаление, кнопки заблокированы, поток удаления не фоновый (закрытие окна не обрывает его на середине).
- **Контекстное меню** списка программ: удалить, принудительное удаление, убрать только запись (с копией),
  открыть папку, показать в regedit, найти в интернете, копировать название.
- **Чистка реестра** (`RegistryCleaner`): записи удаления, у которых нет ни деинсталлятора, ни папки; App Paths,
  автозапуск, SharedDLLs, `Installer\Folders` и MuiCache, указывающие на отсутствующие файлы. «Отсутствует»
  считается только для полного пути на присутствующем локальном диске (сетевые, съёмные, `Sysnative`,
  запускалки вроде `rundll32` не судятся); для 32-битных записей проверяется и `SysWOW64`.
- **Все пользователи.** От имени администратора (особенно если в UAC введён пароль другой учётной записи)
  собственный `%LOCALAPPDATA%` — не тот пользователь, что сидит за ПК. Поэтому Temp, кэши программ, шейдеров,
  дампы и браузеры берутся по всем профилям из `ProfileList` (`UserProfiles`), а программы и остатки в реестре —
  из `HKEY_USERS` всех вошедших пользователей. Реестр невошедших пользователей — закрытый файл, его не трогаем.
  Свои деинсталляторы пользователя рабочего стола запускаются от его имени; чужие — только принудительно.
  «Браузер запущен» и его закрытие касаются только процессов владельца профиля (на терминальном сервере не
  закрываются браузеры других сеансов).

## Безопасность (приложение работает от администратора)

- **Удаление** (`Secure.Delete`): файл открывается с `FILE_FLAG_OPEN_REPARSE_POINT`, проверяется, что это не
  reparse point и что его реальный путь (`GetFinalPathNameByHandle`) внутри реального корня цели, и только
  потом удаляется через тот же дескриптор. Подмена папки на junction между анализом и удалением не срабатывает
  (проверено тестом).
- **Корни** очистки не могут быть корнем диска, Windows, профилем, Program Files, AppData и т. п. (`FileOps.IsSafeRoot`).
- **Автозапуск**: задача с наивысшими правами запускает копию из `%ProgramFiles%\Wisp Cleaner` (туда пишут только
  администраторы), а не exe из «Загрузок» — иначе подмена exe давала бы права администратора при входе.
  Выключение удаляет задачу и копию.
- **Программы пользователя**: деинсталляторы из `HKCU` и браузер (страница расширений) запускаются с обычными правами
  пользователя (токен проводника), а не от администратора.
- **Остатки**: имена из реестра без `..` и недопустимых символов, папка должна быть похожа на имя программы, папки,
  где лежат другие установленные программы, не предлагаются. Папки — в Корзину, реестр — с `.reg`-копией в
  `WispCleaner Backup`.

## Что проверено, а что нет

Проверено (сессия без прав администратора, `WispCleaner.dev.exe`):
- сборка; все вкладки в обеих темах и на обоих языках, в том числе при минимальном размере окна (скриншоты);
- тест-утилита на исходниках (25 проверок): возраст файлов, read-only, занятый файл, junction наружу,
  **junction, подставленный между анализом и удалением**, запрещённые корни, дубликаты, разбор командных строк,
  тихое удаление тестовой программы из HKCU и поиск её остатков;
- утечки: 40 переключений вкладок — GDI/USER-объекты без изменений;
- новый логотип: PNG всех размеров 16–256 px на тёмном и светлом фоне, скриншот шапки и заголовка окна;

## Подводные камни

- C# 5: нет `$""`, `?.`, `nameof`. Глифы Segoe MDL2 писать только как `\uXXXX`.
- Видимость контролов на скрытой вкладке всегда `false` — в раскладке не опираться на `Control.Visible`.
- Всё, что рисуется только в `WM_PAINT`, должно рисоваться и в `WM_PRINTCLIENT` (снимки для переходов).
- Текст рисовать только через `TextDraw` (не `TextRenderer` напрямую). Массовая замена `TextRenderer.` → `TextDraw.`
  не должна задевать сам `TextDraw.cs` — иначе он вызывает сам себя (переполнение стека при запуске).
- Значки Segoe MDL2 в исходниках — только `\uXXXX`: инструменты, которые раскрывают `\u` в строке, кладут в файл
  сам символ из частной области (так было с `AppsPage.cs`, исправлено скриптом).
- Значения из реестра читать как есть (`Reg.Str`, `DoNotExpandEnvironmentNames`) и раскрывать через
  `UserProfiles.Expand(текст, sid владельца)`: `GetValue` по умолчанию раскрывает `%VARS%` под учётную запись программы.
- Общий каркас с DriveUP: улучшения интерфейса удобно переносить в обе стороны (`diff` с заменой `namespace`).
- Размеры задавать в дизайн-пикселях так, чтобы они пересчитывались при смене масштаба: в раскладке
  (`S()` при каждом вызове), через `FlatButton.SetBaseHeight`, `Card.TitleBase`, или в `ApplyScale()`
  страницы/контрола. `X.Height = S(..)` в конструкторе останется прежним после смены масштаба.
- `WispCleaner.dev.exe` — отдельный экземпляр (`Program.Instance` = `WispCleaner.Dev`): свой мьютекс и
  сообщение «показать», поэтому проверки `/tab:N` не трогают запущенную рабочую копию.
- Таблицы: `OnDrawSubItem` не вызывается — строки рисует `ThemedListView.DrawRow` (перехват `NM_CUSTOMDRAW`).
  Новое в ячейке рисовать там; структуры уведомлений — с вложенным `NMHDR` (выравнивание на x64).
- `Transition.CrossFade` внутри области, где уже идёт переход, откладывается до его конца: состояние,
  которое читают сразу после вызова, держать в полях страницы (`cats`, `groups`), а не в списке на экране.
- Длительности перехода вкладки и полоски под вкладкой совпадают (260 мс): первая настоящая отрисовка новой
  страницы приходится на момент, когда ничего не движется.
- Server-версии Windows обычно без приложений Store — пустой список там нормален.
- Приложение запускается в одном экземпляре: пока открыта любая копия (в т. ч. в трее), `build.cmd` не может
  перезаписать `bin\WispCleaner.exe` (CS0016), а второй запуск лишь показывает уже открытое окно.
- Проверки без мыши: `WispCleaner.dev.exe /tab:N` открывает вкладку N, а для уже запущенной копии переключает её
  (так снимались скриншоты всех вкладок).

## Как проверять от администратора

1. `build.cmd`, запустить `bin\WispCleaner.exe` (UAC).
2. Создать мусор: файлы старше суток в `%LOCALAPPDATA%\Temp\WispTest` и `C:\Windows\Temp\WispTest`
   (`(Get-Item f).LastWriteTime = (Get-Date).AddDays(-2)`; то же для CreationTime) → «Очистить» → файлы удалены.
3. Тестовая программа: ключ `HKLM\...\Uninstall\WispTest` с `QuietUninstallString` = `cmd /c reg delete ... /f`
   → удалить из «Программ» → строка исчезла, предложены остатки.
4. Принудительное удаление: программа с удалённым вручную деинсталлятором (или тестовая запись в HKLM с
   несуществующим `UninstallString` и папкой в Program Files, службой `sc create WispTestSvc binPath= ...` и задачей)
   → красная точка → «Принудительно» → в списке папка, служба, задача, запись → «Убрать отмеченное» →
   всё исчезло, в `WispCleaner Backup` копии.
5. Второй пользователь: файлы старше суток в его `AppData\Local\Temp` → на «Очистке» пункт «Временные файлы
   пользователей (N)» включает их; «Браузеры» показывают его профили с его именем.
6. Включить автоочистку «Мало места» с порогом выше свободного места → через минуту уведомление в трее.
   Включить «Запускать с Windows» → `schtasks /query /tn "Wisp Cleaner"`, папка `C:\Program Files\Wisp Cleaner`;
   выключить → задача и папка исчезли.
